### Koha Updates
- Fix an issue where requesting a password reset for a Koha patron could display a misleading "patron not found" error; the outcome and any messages returned by Koha are now surfaced in Aspen, and the redundant Aspen account lookup is skipped once the patron is found in the ILS. ([DIS-2375](https://aspen-discovery.atlassian.net/browse/DIS-2375)) (*CZ*)
- Continue to check non-ILS accounts (such as administrator users) against the Aspen database when the ILS returns no match, so their password reset and email resend requests are still handled. ([DIS-2375](https://aspen-discovery.atlassian.net/browse/DIS-2375)) (*CZ*)
#### Staff Registration of New ILS Patrons
##### Configuration
- Administrators can allow staff to register new ILS patron accounts from within Aspen via a new library setting. ([DIS-2287](https://aspen-discovery.atlassian.net/browse/DIS-2287)) (*CZ*)
- Staff registration of new ILS patrons is controlled by three new permissions: ([DIS-2287](https://aspen-discovery.atlassian.net/browse/DIS-2287)) (*CZ*)
    - register patrons with any home library.
    - register only patrons whose home library matches the staff member's.
    - register only patrons whose home location matches the staff member's.
##### Staff Experience
- Staff with the appropriate permission can access a new Register Patron page from a new Patron Management section of the admin area. ([DIS-2287](https://aspen-discovery.atlassian.net/browse/DIS-2287)) (*CZ*)
- The registration form is built from the ILS's own patron registration fields, honouring the ILS's mandatory and unwanted field configuration. ([DIS-2287](https://aspen-discovery.atlassian.net/browse/DIS-2287)) (*CZ*)
- The form adapts to the selected patron category: ([DIS-2287](https://aspen-discovery.atlassian.net/browse/DIS-2287)) (*CZ*)
    - for organisation categories, personal name fields are hidden, the surname field is relabelled "Name", and the identity section is relabelled "Organisation Identity".
    - a guarantor can be recorded, and is required when the selected category is a child (or is otherwise allowed to have a guarantor) and the ILS requires one for such patrons.
- If the submission fails validation or is rejected by the ILS, the form is redisplayed with the previously entered values preserved and the reason shown. ([DIS-2287](https://aspen-discovery.atlassian.net/browse/DIS-2287)) (*CZ*)
- On success, the new patron's credentials (barcode, username, and initial password where applicable) are displayed once, with a reminder that they will not be shown again. ([DIS-2287](https://aspen-discovery.atlassian.net/browse/DIS-2287)) (*CZ*)
