#### Indexing
- Java indexers and extractors are now started with the JVM options from the new `[JavaProcesses]` section of config.ini. By default every process exits on an out of memory error so it is restarted cleanly, and its heap is capped at a share of the server's (or container's) memory: 25% for the reindexer, the ILS extractors and side loads, 5% for the list, series, course reserves, events and website indexers, and 12% for everything else. Sites can override the options for any process in their own config.ini. Processes started from cron now go through `cron/runJavaProcess.php`; existing cron settings are updated during the upgrade, and on Docker when the cron container starts. In Docker the options can also be set with the `ASPEN_JAVA_OPTS` and `<PROCESS>_OPTS` (e.g. `KOHA_EXPORT_OPTS`) environment variables. Set `enabled = false` in `[JavaProcesses]` to start the processes with a plain `java -jar` as before. The console output of the background processes, including out of memory errors, is now kept in `<process>_output.log` next to their logs. ([DIS-3191](https://aspen-discovery.atlassian.net/browse/DIS-3191)) (*TC*)
